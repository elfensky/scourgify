<objective>
Turn adjudication and backfill into menu verbs: `promote` runs the advocate-and-skeptic pass on a
judge-capable engine and offers the same per-candidate verdict review the wizard offers, and
`backfill` closes the loop by writing promoted and aliased tags onto exactly the books that proposed
them.

Purpose: `proposed_new` candidates are never written to books, so a promotion that is never backfilled
leaves the source books untagged *and* stamped — invisible to the incremental scope forever. Both
halves have to be reachable without a terminal for the loop to close in the GUI. And #73's ask
envelope is what lets a promote refusal offer the same "retry on another engine" recovery a classify
refusal already does.

Output: the `(text, err)` envelope and the failure class on the ledger reason, the promote and
backfill jobs, and two live menu slots.
</objective>

The #73 gap, verified in source (promote.py:408-427 and 118-137):
  run()'s defaults slice the tuple:  ask = lambda p: ask_retry(eng, p)[0]
                                     verify_ask = lambda p: ask_retry(veng, p)[0]
  decide() therefore sees a bare string and, on a transport failure, records
  reason="no usable response (transport failure or unparseable)" with no class prefix, so
  engines.failure_class() cannot read a class back out of it.
  classify's and synopsis's ask shape is the FULL tuple:  ask = lambda p: ask_retry(eng, p)
  engines.ask_retry(eng, prompt, tries=4) -> (text, err), where err already carries the class prefix.

("unclassified — review manually"). Per the fallback protocol an unclassified row is never
auto-resolved and never silently dropped; it is surfaced here for the developer:

- **WRITE-05 / unclassified.** The probe could not classify WRITE-05 into an edge category. The
  planner's reading is that its hazard is a *consent* hazard rather than a data-shape one — a verdict
  recorded that the user never ticked, which then permanently retires a candidate — so it is carried
  as a prohibition and as an explicit truth about the ledger, not as an edge. If the developer sees a
  data-shape edge here the planner missed (an alias-target collision, a candidate appearing in two
  ranked artifacts at once), say so and it will be added as an explicit truth.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM verdict text → the user's overrides directory | an adjudication result becomes a persistent vocabulary or alias rule |
| reviewer's tick state → the ledger | an unticked verdict must leave no record at all |
| plugin job → live Calibre library handle | the backfill write |
| stored API key → engine constructor / ledger reason / dialog | a secret crossing into a persisted or displayed surface |
