<objective>
Give CI a green `windows-latest` lane and a `calibre-debug` smoke on both Windows and Linux.

Purpose: Windows and macOS are this milestone's acceptance targets, and every later phase adds Qt
code that a late cross-platform handoff would discover the hard way. The lane also settles the one
fact this phase's research could not verify from a mac: where `calibre-debug.exe` actually lands on
a fresh `windows-latest` runner after a silent MSI install. Landing the lane FIRST — not gated
behind the refactor plans — is what makes a red run surface an installer or path problem
immediately.

Output: two new required Windows jobs and one new Ubuntu smoke job in `.github/workflows/ci.yml`,
plus a settled answer for the `calibre-debug.exe` path recorded in the summary.
</objective>

    Add two more jobs to `.github/workflows/ci.yml`: `smoke-calibre-windows` (`windows-latest`) and
    `smoke-calibre-linux` (`ubuntu-latest`). Both run `tests/smoke_calibre.py` under Calibre's own
    interpreter, which is the one property the plain-assert suite cannot assert.

    Pin the Calibre version ONCE, as a workflow-level `env:` key (name it `CALIBRE_VERSION`, value
    `9.11.0` unless a newer official release is current at execution time — record which was used in
    the summary). Both jobs read it. D-13 makes bumping it a visible commit; two copies of the
    number would defeat that.

    Windows job steps:
    - checkout, then `actions/cache@v4` keyed on the runner OS plus `CALIBRE_VERSION`, caching the
      downloaded installer file so a re-run does not re-download.
    - Download `calibre-64bit-${CALIBRE_VERSION}.msi` from `download.calibre-ebook.com` on a cache
      miss.
    - Install silently with `msiexec /i <file> /qn /norestart` and wait for it to finish.
    - RESOLVE `calibre-debug.exe` rather than hard-coding it: try `Get-Command calibre-debug` first,
      then the conventional 64-bit install dir, then a bounded search under the Program Files roots.
      If none is found, fail the step printing every path that was searched — the CI lane is where
      this fact gets settled (STATE.md records it as unverified), so a failure must say exactly what
      was looked for.
    - Run the resolved binary as `calibre-debug -e tests/smoke_calibre.py`. Do NOT set
      `CALIBRE_LIBRARY`: with it unset the smoke exercises the import and module-level paths only,
      which is the CI-safe half; a library is a manual-pass concern.

    Linux job steps: the same shape using the official Linux installer script from
    `download.calibre-ebook.com`, pinned to the same `CALIBRE_VERSION`, installed non-interactively
    to a workspace-local prefix so no sudo prompt is needed, then the same
    `calibre-debug -e tests/smoke_calibre.py` invocation. Today `ci.yml` has no Calibre install step
    on any OS — treat both as first-time integration work, not a flag added to an existing step.

    Both jobs are blocking from day one (D-12). If the download turns out to be flaky, the agreed
    fallback is to demote ONLY the smoke jobs, as a visible edit to this file — not to make them
    non-blocking pre-emptively here.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner -> download.calibre-ebook.com | An installer binary is fetched over the network and executed with elevated rights on the runner |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Tampering | the Calibre installer fetched in the smoke jobs | medium | mitigate | Fetch only over HTTPS from the vendor's own `download.calibre-ebook.com`, at a version pinned once in `ci.yml`; bumping it is a visible commit (D-13). The runner is ephemeral and the job holds `permissions: contents: read` |
| T-01-08 | Elevation of Privilege | `msiexec /qn` on the runner | low | accept | GitHub-hosted runners are single-use and disposable; the installer runs with the runner's own rights and nothing from the repository is passed to it |
| T-01-09 | Denial of Service | smoke jobs blocking every PR on a third-party download | medium | accept | Accepted deliberately per D-12: both jobs are blocking from day one, and the agreed remedy for a flaky download is a visible `ci.yml` edit demoting only the smoke job — not a silent `continue-on-error` |
| T-01-SC | Tampering | package-manager installs | n/a | accept | No package is added or upgraded by this plan. The only third-party artifacts are pinned GitHub Actions (`actions/checkout@v6.0.2`, `astral-sh/setup-uv@v8.1.0`, `actions/cache`) already in use or version-pinned here |
