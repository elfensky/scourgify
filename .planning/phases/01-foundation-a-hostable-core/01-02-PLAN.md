<objective>
Give CI a green `windows-latest` lane and a `calibre-debug` smoke on both Windows and Linux.

Purpose: Windows and macOS are this milestone's acceptance targets, and every later phase adds Qt
code that a late cross-platform handoff would discover the hard way. The lane also settles the one
fact this phase's research could not verify from a mac: where `calibre-debug.exe` actually lands on
a fresh `windows-latest` runner after a silent MSI install. Landing the lane FIRST — not gated
behind the refactor plans — is what makes a red run surface an installer or path problem
immediately.

Output: two new blocking Windows jobs and one new Ubuntu smoke job in `.github/workflows/ci.yml`,
plus a settled answer for the `calibre-debug.exe` path recorded in the summary.

**Scope of XPLAT-01 in this phase — read this before treating the requirement as closed.**
XPLAT-01 says "The plugin loads AND every core module imports under Windows Calibre's bundled
Python 3.14". Those are two claims and this phase delivers one of them:

- **Delivered here:** every core module imports and reads under Windows Calibre's own interpreter,
  proved by `smoke-calibre-windows` running `tests/smoke_calibre.py` through `calibre-debug -e`,
  plus `test-windows` running the whole plain-assert suite on CPython 3.14. That is what closes the
  "no `pgrep`, no `chmod` assumptions, no POSIX-only paths" half.
- **Deferred to Phase 6** (XPLAT-05 — the recorded manual pass in real Calibre on macOS and
  Windows): "the plugin loads". Two reasons, both structural rather than budgetary. There is no
  plugin-side code to load in Phase 1 — the write verbs arrive in Phase 2 and the panel in Phase 4 —
  and a headless GitHub runner cannot load a Qt `InterfaceAction` into a running Calibre GUI, so any
  Phase-1 assertion would prove something other than what the requirement says. Phase 6 already owns
  a handoff checklist (XPLAT-04) and the recorded two-platform pass (XPLAT-05); that is the right
  home, and it is where the claim becomes checkable.

Stated here rather than only in `<flagged_planner_assumptions>` so a reader of this plan cannot come
away believing an import smoke proved a plugin load.
</objective>
