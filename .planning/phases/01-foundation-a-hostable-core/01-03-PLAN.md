<objective>
Give the bundled read-only data a resource seam, so the core reads its own defaults whether it runs
from an installed wheel or from inside the plugin zip — and make the apple engine cleanly absent
off macOS.

Purpose: inside the zip, `common.HERE` is a zip-internal path, so `os.path.exists()` is False for
every bundled CSV. `load_maps()` already fails closed on that (found in plugin phase 4), which is
why the plugin is read-only today; `load_vocab()` does not, and would silently hand the classifier
an empty controlled vocabulary. `engines.Apple` independently builds its command off the same raw
constant, which is a third failure mode with a different symptom. One resolver closes all three.
The apple platform trait rides along because it is the same neighbourhood: whether the on-device
engine can run here at all.

Output: `common.defaults_dir()`, three repointed consumers, a `platforms` trait row, and a test that
builds a real zip and proves the cost estimate is identical either way.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03 | Tampering | `common.defaults_dir()` zip extraction (CWE-22, zip-slip and symlinked intermediate dirs) | medium | mitigate | Every member's destination is resolved with `os.path.realpath` and refused with `GuardrailError` unless it stays under the realpath of the extraction root (which also rejects a symlinked intermediate directory); destinations open with `"xb"` so an unexpected pre-existing file is an error, not an overwrite. The archive is the plugin's own build output, so this is defence in depth rather than an untrusted-input path |
| T-01-10 | Tampering | `load_maps()` / `load_vocab()` against an empty or partial extraction | high | mitigate | Both fail closed with `GuardrailError`; the extraction writes its marker file LAST *inside a unique temp tree* and that tree is moved into place with a single `os.rename` only when the target is absent, so a half-extraction is never mistaken for a warm cache and a failed attempt is `rmtree`d rather than left behind |
| T-01-24 | Denial of Service | two Calibre jobs extracting into `user_dir()/cache/` at the same moment | medium | mitigate | Each extraction uses a pid- and nonce-unique `.tmp-` directory, so neither can see the other's partial state; the loser of the final `os.rename` discards its temp tree and reads the winner's warm cache. `os.replace` onto an existing directory — which would let one job pull the tree out from under the other, and which is not portable to Windows — is banned by a source assertion |
| T-01-11 | Spoofing | stale cache after a core upgrade | medium | mitigate | The cache directory is keyed by the core version read from the zip's own stamped `_plugin_version.VERSION`, so a version bump extracts afresh rather than reading the previous release's data |
| T-01-12 | Information Disclosure | extraction cache under `user_dir()/cache/` | low | accept | The extracted content is the shipped public defaults — the same bytes as the installed wheel. No secret or per-library data is written there |
| T-01-SC | Tampering | package-manager installs | n/a | accept | No package is added or upgraded. `zipfile` and `importlib.metadata` are stdlib and already used in this repository |
