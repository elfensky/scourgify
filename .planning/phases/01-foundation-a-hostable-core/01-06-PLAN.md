<objective>
Make the one shared pre-write protocol refuse to overwrite a value that changed since the plan was
computed: skip that `(book, field)`, report it by book, and log the run honestly.

Purpose: every plan in this tool is computed against a read, then applied later — sometimes minutes
later, sometimes after the user edited the book in Calibre in between. Today the write applies
regardless, so the user's more recent edit is silently lost. `editlog.conflict` already exists as
the pure, tested predicate for exactly this question, because undo needs the same verdict; this
plan puts it on the apply side too, in the ONE funnel plan 01-04 built, so the two can never come to
mean different things.

Output: an `expected` mapping on the write op, a conflict filter in the shared funnel, a `skipped`
list in the run footer and in the funnel's returned result, CLI output naming each skipped book, and
every producer populating `expected` from the before-state its plan was computed against.
</objective>

**Stated planner assumption on the op key shape (research Open Question 3, no user input taken):**
`expected` mirrors the existing `values` shape exactly — `{book_id: expected_value}` on the
`set_field` op, alongside `values`. Rationale: every consumer that already reads `values` needs
near-identical handling, and symmetry removes the chance of the two dicts drifting in key type
(string from JSON, int in process) the way `ops.coerce`'s own docstring warns about for `values`
alone. This matches the orchestrator's resolved recommendation.

## Trust Boundaries

| Boundary | Description |

| plan time -> apply time | The library can change between the read a plan was computed from and the write that applies it — by the user in Calibre, by FanFicFare, or by another scourgify run |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05 | Tampering | the shared pre-write protocol's apply step | high | mitigate | `_check_conflicts` compares the fresh before-read against the op's plan-time `expected` with `editlog.conflict` and drops the drifted `(book, field)` before logging and before applying — skip and report, never overwrite |
| T-01-20 | Repudiation | a skipped write disappearing from the record | high | mitigate | The footer carries the skipped pairs and their count, the funnel returns them, both transports print them by book, and an all-skipped run still writes a header and footer so the attempt is in History |
| T-01-21 | Tampering | two different definitions of "conflict" between apply and undo | medium | mitigate | `editlog.conflict` is the single predicate; the plan forbids writing a second equality test in `common.py`, and the acceptance criteria assert it |
| T-01-22 | Tampering | an op line describing a write that never landed | low | accept | Accepted by design and unchanged: op lines are written before the apply because that is the only ordering that survives a crash, and undo is conflict-aware, so a never-landed op reads as a conflict and is skipped rather than clobbered |
| T-01-SC | Tampering | package-manager installs | n/a | accept | No package is added or upgraded; the predicate and both readers already exist in this repository |
