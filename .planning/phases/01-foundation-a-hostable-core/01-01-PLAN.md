<objective>
Make the library uuid the primary key for every piece of scourgify's operational state, and make
`user_dir()` resolve on Windows.

Purpose: this is the tracer for "the unchanged core runs correctly when hosted". A plugin opens
whatever library the GUI has open and switches libraries mid-session; today every artifact path is
a pure function of `user_dir()` alone, so a throwaway library reads and writes the real library's
proposals, failures, edit log, backups, rejects and ledger. That bleed was observed once in plugin
phases 4-5. Every later plan in this phase (the write-run lock keyed by uuid, the per-library edit
log the conflict check writes) depends on this resolution existing.

Output: `common.data_dir()` resolving under `data/<library uuid>/`, a Windows branch in
`common.user_dir()`, a one-time guarded migration of the existing flat tree, and a contract test
that fails loudly if any future phase reintroduces a library-less artifact path.
</objective>

<assumption_delta_decision>
**Detector:** `kind: pluralization`, term "second", from "A second write job against the same library".

**The noun that is now primary — two of them, both promoted:**

1. **The library uuid is the primary key for all operational state.** The old single global
   `user_dir()/data/` tree is not a parallel path beside the new one; it is ONE VARIANT of the
   uuid-keyed tree — the current library's — and reaching it goes through the same
   `common.data_dir()` resolution as any other library. There is no "default" or "global" artifact
   path any more.
2. **The pre-write protocol is primary; `run_writer` and `write_ops` are two transports of it.**
   (Implemented in plan 01-04; recorded here because it is the same delta.) The sequence
   guard -> lock -> before-read -> conflict check -> backup -> log -> apply is the thing; the
   subprocess vs in-process apply is a parameter of it.

**Decision: `promote`.**

**Rationale:** CONTEXT.md D-01 locks the uuid level into `data/<uuid>/` and D-02/D-03 lock a
migration of the existing tree into it, which is the definition of promoting the plural to primary
rather than adding a second path alongside. Keeping the flat tree as a co-equal "no library" path
would recreate exactly the bleed this phase exists to close: whichever library resolved first would
own it. `config.toml` and `overrides/` are deliberately NOT promoted (D-01) — they stay singular at
the `user_dir()` root, and CONTEXT.md records "per-library config.toml" as a deferred idea.

**Invariant test encoding the generalized intent (Task 1):**
`tests/test_paths.py::test_every_artifact_path_is_library_scoped` enumerates every artifact path
function in the codebase and asserts each one resolves under `data/<uuid>/` for BOTH of two
libraries opened in sequence in one process. A future phase that adds an artifact path built on
`user_dir()` directly, or that reintroduces a library-less default, goes red on that test rather
than shipping a second bleed.
</assumption_delta_decision>
