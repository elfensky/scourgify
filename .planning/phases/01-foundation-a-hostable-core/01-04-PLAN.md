<objective>
Collapse the two copies of the pre-write sequence into one function both transports call, put a
library-uuid-keyed write-run lock at its head, and prove that nothing a Calibre job can reach
shells out.

Purpose: `common.write_ops` (in-process) and `common.run_writer` (CLI subprocess) independently
sequence guard, before-read, snapshot and log today. That duplication is what this phase's roadmap
goal means by "closes the pre-write protocol half of #71", and it is the precondition for the
apply-time conflict check in plan 01-06 landing ONCE instead of twice with two slightly different
edge-case behaviours. The lock belongs at the head of that one sequence because a second concurrent
write against a live library is the highest-consequence failure this milestone can produce.

Output: one shared pre-write protocol, a uuid-keyed lock refusing a second write run by name, a
Windows branch in `calibre_open()`, and a source-reading test that pins the no-shelling-out rule.
</objective>

<known_limitations>
Recorded so no later phase reads a stronger claim into this one than it makes.

**One open library per process.** `common._LIBRARY` is a module global and `library()` / `db_path()` /
`data_dir()` / `ro_connect()` all read it. This plan makes the LOCK per library uuid and captures the
run's library path once at the head of the protocol, which removes the "a `set_library()` mid-run
moves the snapshot" hazard. It does NOT make two full write runs against two different libraries in
one process safe — the readers those runs build still resolve through the global. Promoting
`_LIBRARY` to a `ContextVar` (its own docstring already names this as the migration) belongs with the
phase-4 library-switch work that needs it, not here. Nothing in this phase claims or tests concurrent
multi-library writes.

**Cross-process contention is out of scope (D-06).** A CLI write is already refused while the GUI is
open by `calibre_open()`, and CONTEXT.md records an advisory lock file as a deferred idea. No lock
file, no pid probe.
</known_limitations>

| T-01-13 | Denial of Service | a wedged lock after a failed write | medium | mitigate | The lock is released in the context manager's `finally` and the holder record cleared; `test_the_lock_is_released_after_a_failed_run` pins it |
