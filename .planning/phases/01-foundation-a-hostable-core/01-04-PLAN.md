<objective>
Collapse the two copies of the pre-write sequence into one function both transports call, put a
library-uuid-keyed write-run lock at its head, and prove that nothing a Calibre job can reach
shells out.

Purpose: `common.write_ops` (in-process) and `common.run_writer` (CLI subprocess) independently
sequence guard, before-read, snapshot and log today. That duplication is what this phase's roadmap
goal means by "closes the pre-write protocol half of #71", and it is the precondition for the
apply-time conflict check in plan 01-06 landing ONCE instead of twice with two slightly different
edge-case behaviours. The lock belongs at the head of that one sequence because a second concurrent
write against a live library is the highest-consequence failure this milestone can produce.

Output: one shared pre-write protocol, a uuid-keyed lock refusing a second write run by name, a
Windows branch in `calibre_open()`, and a source-reading test that pins the no-shelling-out rule.
</objective>

    - A write run against a DIFFERENT library uuid proceeds while the first still holds its lock

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| two writers -> one metadata.db | Two concurrent write runs against one library is the corruption case every guard in this file exists to prevent |
| job thread -> host OS | A Calibre worker thread reaching a process spawn is the freeze/zombie case the plugin architecture forbids |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering | two concurrent write runs against one library | high | mitigate | A library-uuid-keyed, non-blocking `threading.Lock` acquired at the head of the ONE shared pre-write protocol; the second run raises `GuardrailError` naming the holder and takes no snapshot and writes no log line |
| T-01-13 | Denial of Service | a wedged lock after a failed write | medium | mitigate | The lock is released in the context manager's `finally` and the holder record cleared; `test_the_lock_is_released_after_a_failed_run` pins it |
| T-01-14 | Denial of Service | a `SystemExit` or a blocking acquire inside a Calibre worker thread | high | mitigate | Every new guard raises `GuardrailError`, which `ThreadedJob`'s `except Exception` catches; the acquire is non-blocking, so a double-take raises instead of hanging the worker silently |
| T-01-15 | Elevation of Privilege | process spawn from job-reachable code | medium | mitigate | An AST assertion in `tests/test_plugin_safety.py` restricts spawns to an enumerated exemption list and names the offender on failure; `setup`'s inline shell-out is extracted into one injectable named seam |
| T-01-16 | Spoofing | a Windows process named like Calibre defeating the open-GUI guard | low | accept | `tasklist` filters on image name and the existing exclusion discipline drops the CLI tools and workers; a deliberately misnamed local process is not in this desktop tool's threat model, and the guard fails closed when it cannot tell |
| T-01-SC | Tampering | package-manager installs | n/a | accept | No package is added or upgraded. `threading`, `ast` and `subprocess` are stdlib and already used here |
